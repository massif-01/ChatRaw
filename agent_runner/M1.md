# A / M1 Runner 交接

本批实现宿主执行服务，未接入 ChatRaw 网关和真实 Hermes；后者是下一批 M2。
公共 base.py / v1 签名未改。原生适配器通过固定注册表加载，每 session 一个实例。

## 启动与接口

Python 3.11+，`pip install -r agent_runner/requirements.txt`，然后：

```sh
python -m agent_runner --config /etc/chatraw-runner/config.json
```

配置含 `data_dir`、`token_file`、`port`（默认51112）、`host`（仅 loopback）、
`max_concurrency`（默认3）、`agents`（Agent ID→宿主私有配置）、
`workspaces`（项目ID→`{path,label}`）。token 至少32字符，单独私密文件，不能放浏览器。
启动锁住独立数据目录；同目录不能运行第二个 Runner。

所有端点要求 `Authorization: Bearer <专用凭据>`；session/run/file资源还要求
`X-ChatRaw-Chat-Id`，Runner再次对照持久归属。不存在无认证 health 例外。

|方法/路径|用途|
|---|---|
|GET /v1/health|service/schema_version握手|
|GET /v1/agents；GET /v1/agents/{id}/health|可用性/能力/逐层检查；前者另含settings_schema|
|PUT /v1/agents/{id}|`{enabled,settings?}`；settings仅允许adapter声明的JSON Schema字段|
|GET /v1/workspaces|仅ID/label|
|POST /v1/sessions|`{session_id,chat_id,agent_id,workspace}`；session_id由ChatRaw后端预分配并持久化|
|GET /v1/sessions/{id}|绑定、活动run、最近run|
|POST /v1/runs|`{session_id,chat_id,client_request_id,message,attachments}`；202|
|GET /v1/runs?chat_id=&client_request_id=|查准入结果，不隐式补发|
|GET /v1/runs/{id}；GET /v1/runs/{id}/events?after=|快照/可重放NDJSON；空行仅心跳|
|POST /v1/runs/{id}/cancel|显式停止；返回当前实际状态|
|POST /v1/runs/{id}/interactions/{iid}/reply|原合同的answers/decision_id/cancelled三种形状|
|POST /v1/sessions/{id}/compact|`{client_request_id}`；相同准入与停止路径|
|POST /v1/attachments?session_id=|宿主内部传输为原始bytes、X-Filename、Content-Type；浏览器端仍multipart|
|GET /v1/artifacts/{id}|受控副本下载，无任意路径入口|

叶模块注册名：`HermesAdapter` / `CodexAdapter` / `ClaudeAdapter` / `PiAdapter` /
`DeepSeekAdapter`，位于对应的固定模块。模块未交付则显示 unavailable；已交付但依赖损坏
不会被当作“未安装”静默吞掉。没有下载或安装SDK的启动副作用。

## 已实现的保证与边界

- SQLite WAL + synchronous FULL；状态、交互、幂等身份、绑定检查点和事件提交后可读取。
  done与终态同事务；本批每段文本直接落盘，没有额外批次丢失窗口。
- 上游创建与本地事务仍有分布式未知窗口；创建session先保存reservation，未知时不重复创建。
  请求准入先保存键再启动；重启对已派发运行调用recover_run，不重发prompt。
- queued在重启时可确认为未派发而 interrupted；running/waiting/stopping/unknown始终占位。
  unknown也占总并发限额；不能通过新键或compact绕开。
- cancel/reply使用同run控制锁，锁不覆盖模型运行；重复同回复不再次转发。
  原生回复dispatch失败保存unknown接收结果，禁止自动重传。
- HTTP流只订阅日志，关闭不取消任务；状态快照和事件读取来自同一账本。
  响应丢失后可按原键找回run，终态final_text为权威全文。
- 产物只允许workspace内普通文件，逐层目录FD + O_NOFOLLOW阻止符号链接穿越；
  复制到Runner私有文件目录后下载。此处不宣称cwd是权限沙箱，不能阻止同UID恶意进程修改任意目录。
- 配置以session为边界快照；进行中的运行不随设置修改而改变。既有session继续使用其快照，
  新设置用于新session（后续需要刷新旧session配置时须明确恢复边界）。
- Runner内部cancel若原生状态无法核实会返回unknown，避免伪装stopping已可确认；
  v1浏览器cancel响应枚举未列unknown，网关应将这种情况返回明确错误并读取run快照，
  或由总控补充该枚举。未私改公共合同。

## 验证

```sh
.venv/bin/python -m unittest discover -s agent_runner/tests -v
.venv/bin/python -m compileall -q agent_runner
.venv/bin/python -m flake8 --select=E9,F63,F7,F82 agent_runner
git diff --check
```

本机Python3.12.4运行，真实loopback HTTP + SQLite，原生接收端为ControlledAdapter。
测试有可控批准/停止屏障与最终文件标记、重复准入/响应、跨run拒绝、重启不重发、断线重放、
附件归属、符号链接拒绝与下载副本、问答批次反例。不是五Agent实测或RM01验收。
本批只有新agent_runner模块，不修改ChatRaw数据，无生产迁移/重启要求；未push或部署。
