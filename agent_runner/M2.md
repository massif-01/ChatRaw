# A / M2 集成交付

范围：统一宿主Runner、ChatRaw同源API、绑定与准入/显示迁移、Hermes原生Gateway适配、
附件/产物、官方插件本地安装、Docker及宿主systemd交付。公共adapter base与浏览器v1签名保持。
不修改B/E界面或C/D叶模块。C/D提交仅用于接线和测试，修复由原owner提交。

## 实际行为

- 所有新Agent输入走统一API。普通聊天的历史/summary/system/Skill/RAG路径在绑定检查后独立运行，
  Agent输入不会进入这些构造器。绑定后的聊天不能通过普通chat或普通compact绕过。
- 有消息、活动运行或不明准入的聊天不能改绑；活动/unknown运行阻止删除。旧的普通聊天10条
  保留规则不再隐式删除Agent聊天。既有文本、模型、插件设置与独立密钥资料保留。
- 浏览器刷新通过chat绑定取回active_run_id；202丢失按原client_request_id查询，未知不自动重发。
  ChatRaw后台独立同步run结果，即使没有浏览器订阅也按run_id只保存一份用户/最终助手消息。
- Runner是唯一运行权威。持久化终态与done同事务；显式空final_text也替换累计正文。
  断开订阅不停止执行；unknown继续占session及总并发位，旧交互在恢复前失效。
- reply/cancel/禁用在Runner控制点排序；同回复复用持久接收凭据。原生接收ACK丢失不重发批准。
  控制请求掉线不会中断后台停止；插件禁用先关闭ChatRaw准入，再向Runner收敛活动运行。
- 安全settings_schema从Runner透传；即使尚未配置宿主账户也可以保存schema允许的非秘密字段。
  当前执行用原快照，下一次执行在空闲close/resume边界应用新设置。宿主身份/连接配置不改旧绑定。
- Hermes使用canonical Gateway，其实际cwd由原生session.create确认。旧HTTP执行代码与活动集合
  已从生产模块删除，旧执行入口返回410；旧配置不自动改指新目标。
- 附件按chat/session归属与能力/声明大小限制接纳。产物从受控workspace复制后下载，拒绝符号链接
  越界；Hermes原生tool.complete提供的workspace内image_path可登记为产物。通用文件输入不伪造支持。
- `POST /api/plugins/install-bundled {"plugin_id":"..."}`只安装镜像市场已列出的完整目录，含lib/fonts。
  保留现有settings/enabled及独立keys；无网络请求，不放宽通用proxy。原URL/ZIP安装入口保留。
- 基础Compose普通聊天无需Runner。Agent部署明确叠加`deploy/docker-compose.agent.yml`，
  专用token文件只读挂载。原生SDK安装在宿主Runner独立venv，不进入主镜像。

## 接线细节

新API错误为`{error:{code,message,retryable}}`和HTTP状态；旧插件API继续success/error字符串。
Runner鉴权、资源归属、settings schema与后台恢复路由见[M1接口表](M1.md)。
浏览器cancel遇到无法确认的原生停止返回409 `stop_unconfirmed`，后续读取run可见unknown，
不私自扩大v1 cancel成功响应枚举。

GET聊天messages对Agent生成的消息增补`run_id`，旧消息字段不变。
GET agents除v1列表字段外返回adapter的安全`settings_schema`，health.models仅来自原生探测。
图片/文件能力及limits可用于选择器提示；服务端仍再次验证。
保存settings使用现有`POST /api/plugins/{id}/settings`；凭据不属于schema。
