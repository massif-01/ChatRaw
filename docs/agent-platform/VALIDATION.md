## DeepSeek 现场审批收尾

三次尝试均在独立验收聊天内：第一轮模型返回空工具参数并报MALFORMED_RESPONSE；简化后首次参数有效但宿主沙箱不可用，模型后续又返回空参数；第三轮使用官方支持的首调用单次权限申请参数，模型将调用JSON当普通文本返回。都没有收到可供明确提交的公开审批，目标文件均不存在。不存在文件不能证明拒绝路径通过，文本JSON不能当成真实工具调用。

以上是早期失败，不能一概归为模型能力限制。后续按用户要求检查原始请求和响应：此服务的Messages转换忽略Harness原生thinking/output_config，固定请求实际使用关闭思考的模板。仅修正模板选项的对照实验即得到完整工具参数，具体边界见[协议诊断](handoffs/C-local-model-98/deepseek-messages-thinking.md)。

新修复只透传宿主provider，使用Harness内置连接器及版本化v2patch；不改共享模型服务、审批回调或全局沙箱，不执行文本JSON。总控在实际页面分别拒绝及单次允许，A记录原生决定与文件结果，两个独立回合均completed。拒绝目录为空；允许仅写入准确目标，exit0，后续Bash校验仍被沙箱拒绝，没有持续授权。详见[完整现场收尾](reviews/deepseek-approval-20261114/README.md)。

允许回合最终文字错误声称未发生审批。后续经原会话离线原生请求重建、实际模板渲染、三次直接模型生成及原始生成token核对，错误定位到当前模型服务的生成输出，未发现本例调用/结果丢失、错序或响应展示改写。原现场HTTP没有录制的边界仍保留；权重、量化或推理实现的具体细因尚未区分。补退出码或批准事实未得到正确总结，未部署无效补丁，状态为NOT_FIXED，待替代模型资源与真实复验。详见[完整诊断](reviews/deepseek-summary-20261114.md)。G05真实审批结论不变，不能以模型自述替代执行证据。
