## C-F01 · P0 · Codex 已报告取消，但其运行中 shell 继续产生副作用

Owner：C。阻塞 G06，关联 G04/G07 的活动位释放。位置：[codex.py](../../../agent_runner/adapters/codex.py) 644–652、921–954。

根因：`cancel()` 只发送 `turn/interrupt`；收到同一 turn 的 `interrupted` 后立即返回 `cancelled`。原生 `exec_command` 已返回运行中 session 的 shell 不随 turn 结束而自动收敛。适配器仍保留该 app-server，并未确认所属工具进程结束。

**真实原生程序＋本地模型替身复现，两次一致：**

1. 本地模型让真实 Codex 执行临时工作区命令 `printf started > codex-approval-fixture; sleep 5; printf leaked > codex-approval-fixture.late`，`yield_time_ms=1000`；测试显式批准。
2. 确认首个标记存在，且原生已把 `exec_command` 的运行中结果送回模型；保持模型请求活动，再调用 adapter.cancel。
3. 复核 run 在 **0.004 秒**返回 `cancelled`，此时 `.late` **不存在**。
4. 随后 `.late` 出现，证明不是取消前已经完成的操作，而是取消确认之后的继续执行。

同一反例中的 Claude 返回 `cancelled` 后没有产生延迟标记，作为对照通过。

最小修订：让取消的终态条件包含本 session/run 所属原生后台工具的收敛确认；可用当前版本提供的原生 background terminal 管理接口处理，不得影响其他 session。无法确认时保持 unknown，不释放活动位。仅改前端文案、等待 interrupt ACK 或把 interrupted 改名，不能解决根因。实现应同时覆盖“取消时工具刚转为后台”的竞态。

官方协议分别列出了 turn/interrupt 与 thread/backgroundTerminals 的清理/查询/终止接口；turn 终止不能直接替代工具作用域收敛的验收。本发现的依据是实际延迟写入，而不是单凭文档推断。[OpenAI App Server 文档](https://learn.chatgpt.com/docs/app-server#api-overview)

## C-F02 · P1 · 两个 adapter 丢弃审批命令后缀，却允许执行完整命令

Owner：C。阻塞 G05。位置：[codex.py](../../../agent_runner/adapters/codex.py) 205–214、825；[claude.py](../../../agent_runner/adapters/claude.py) 59–66、617–618。

根因：审批使用的 `_preview` / `_safe_preview` 均直接截取前 2048 字符。完整命令不保留在公共审批结构中，也没有拒绝无法审阅的操作。浏览器无法还原已经被 adapter 丢掉的执行内容。

**两种真实程序各复现两次：**发出 `: ` + 2300 个 `x` + `; printf hidden > <临时标记>`。整个 `interaction_requested.data` 都不含 `printf hidden`；测试选择允许后，真实 shell 创建内容为 `hidden` 的标记文件。审批成功并不意味着用户有机会审阅真正将执行的后缀。

最小修订：审批与普通进度预览分开处理。不能完整、准确呈现的过长操作直接拒绝并明确原因，或提供可完整审阅的受控内容再允许提交；不能只加省略号后继续接受对未知后缀的批准。保持必要的凭据保护，同时避免把可执行语法也当作秘密值吞掉。无需为此新建通用权限框架。
